# QA01.1 — Regressão da Sprint 3

Registro da regressão feita sobre o incremento da Sprint 3, antes da apresentação: o que foi
percorrido, os defeitos encontrados e o que foi feito com cada um.

- **Data:** 26/09/2026
- **Base testada:** branch `feat/be02.4-busca-por-proximidade-no-banco` — o incremento completo
  da sprint (todas as atividades já integradas em `prod` mais a BE02.4, ainda em revisão).
- **Critério de avaliação:** o frontend é bem acabado, possui interface limpa, mensagens
  informativas e reage bem mesmo na presença de erro?

## Como foi feita

A regressão foi feita em três camadas, da mais ampla para a mais próxima do usuário.

**1. Verificações automáticas.** As mesmas que o CI roda, mais uma conferência de traduções.

| Verificação | Resultado |
| --- | --- |
| Backend: `./mvnw clean verify` (testes de integração contra MySQL) | 86 testes, 0 falhas |
| App: `npx tsc --noEmit` (checagem de tipos) | sem erros |
| App: `npm run lint` (inclui as regras do React Compiler) | sem erros |
| App: `npm run test:arquitetura` (nenhuma tela chama o backend direto) | aprovado |
| App: toda chave de tradução usada no código existe, e os três idiomas têm as mesmas chaves | aprovado |

**2. Regressão de API.** Um roteiro de 60 chamadas, com as mesmas URLs e os mesmos corpos que a
camada `services/` do app envia, contra o backend rodando com a base de desenvolvimento. Cobre
os fluxos de acesso (login, sessão inválida, recuperação de senha, verificação de conta), perfil,
mapa e busca por proximidade, geração e manutenção de roteiro, avaliações, painel gerencial com
os quatro filtros e administração de usuários — e, para cada um, o caso de erro correspondente,
conferindo que a resposta segue o contrato de erro da OB03.

**3. Percurso no aplicativo.** O app rodando no emulador Android e depois em um celular
(Expo Go), com o backend local, percorrendo as telas e forçando as falhas: dados inválidos, senha
errada, backend fora do ar e aparelho sem internet.

### Por que D12 e D13 ficaram para depois

**D12** não é regressão desta sprint — o módulo de roteiros sempre funcionou assim. Corrigir exige
passar a autorização de todos os endpoints do módulo para o usuário do token e ajustar as chamadas
do app, o que é exatamente o escopo da **OB06 (perfis de acesso)** na Sprint 4. Fazer isso às
vésperas da apresentação arriscaria o fluxo principal do app. Fica registrado como prioridade da
OB06.

**D13** é internacionalização de conteúdo vindo do servidor, escopo da **FE02** na Sprint 4. O
app já recebe o `code` estável de cada erro (contrato da OB03), então a tradução pode ser feita
no app a partir dele.

## Observações que não são defeitos

- **Aba Explorar e o serviço Overpass.** Durante a regressão, o endpoint `/api/tourist-spots`
  (que consulta o Overpass, serviço externo) respondeu 502 por indisponibilidade do serviço — com
  a mensagem do contrato de erro. Nenhuma tela usa esse endpoint hoje (a aba Explorar lê
  `/places`, servido pelo banco), então a demonstração não depende dele.
- **Versão web do app.** `npm run web` não funciona: o `react-native-maps` não tem versão web. O
  app é distribuído só para celular; não é uma regressão.
- **Botão de engrenagem flutuante.** Ao rodar pelo Expo Go aparece um botão de ferramentas no
  canto da tela, que pode cobrir o avatar de perfil. É do próprio Expo Go, não do app, e não
  aparece no aplicativo instalado. Para a demonstração, ele pode ser arrastado para outro canto
  ou desligado no menu do Expo Go.
